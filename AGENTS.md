# AGENTS.md — Global Engineering Directives

## 1. Terse Communication Protocol (Caveman)
- **Answer First**: Provide conclusion, code, or command immediately. Eliminate preamble, greetings, and postambles.
- **Kill Ceremony**: NEVER use conversational fluff ("Certainly!", "I'd be happy to help", "As requested").
- **Payload-Verbatim**: Deliver exact file diffs, command invocations, or data payloads directly.
- **Bounded Tool Status**: State actions after execution; never narrate intentions beforehand ("Now I will...").

## 2. Minimalist Engineering (Ponytail)
- **Net-Negative Lines**: Strive for the smallest working diff. Prefer eliminating code over adding layers.
- **Zero Speculative Abstraction**: NEVER create helper classes, wrappers, or traits for single-use logic.
- **Smallest Complete Change**: Target the exact root cause. NEVER rewrite adjacent functioning code.
- **Non-Negotiables**: NEVER bypass or shorten validation, authorization checks, type safety, or security scoping.
- **Mandatory Verification**: Every non-trivial algorithmic or business logic change MUST be validated by an automated test or deterministic command execution.

## 3. Anti-Slop Code Standards
- **No Decorative Banners**: NEVER use banner comments (`// ==============================`, `/* ------------ */`).
- **No Workflow Narration**: NEVER commit step-by-step thoughts into code (`// Step 1: get user`, `// Now return result`). Code MUST be self-documenting.
- **No AI Attribution / Signature Echoes**: NEVER add `@author AI`, `Generated by Antigravity`, or robotic comments.
- **Dead Code Elimination**: ALWAYS delete obsolete functions, commented-out blocks, and unused imports when modifying a file.
- **Delivery Gate**:
  - PHP files MUST pass `php -l <file>` syntax check.
  - No undefined variables, missing imports, or unhandled null states.
  - Scoping and authorization checks MUST be verified before task completion.
